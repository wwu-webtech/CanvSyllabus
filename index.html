    Pasting it into Canvas

    1. In your Canvas course, open Syllabus from the course menu and click Edit.
    2. Click into the editor where you want the syllabus to go. If there's old content you're replacing, select it and delete it first.
    3. Paste with Ctrl + V, or Cmd + V on a Mac.
    4. Click Update Syllabus.

    If you'd rather work in code, click the </> button at the bottom right of the Canvas editor to switch to the HTML editor, and paste there. The same button gives you the code in that view.

    Paste the normal way

    If you paste with Ctrl + Shift + V, which means "paste as plain text," you'll get the HTML code as text in your syllabus. Undo, and paste with plain Ctrl + V.

    Why this exists

    Pasting from Word into Canvas brings along everything Word knows about fonts, spacing, and colors, wrapped in a pile of HTML that Canvas only partly understands. The result looks almost right until a student opens it on a phone. PDFs can't be pasted at all. So faculty end up rebuilding their syllabus by hand, every term.

    This does the rebuild for you. It keeps the structure (headings, lists, links, bold and italic, tables) and throws away the rest, so Canvas's own styling takes over and the syllabus looks like it belongs in your course.

    What it keeps

    • Headings, moved down one level, because Canvas uses the page title as the top heading
    • Bulleted and numbered lists, including ones typed by hand
    • Bold, italic, and underline
    • Links, and web or email addresses typed as plain text become links
    • Tables, with grid lines and a marked header row

    What it leaves out

    • Fonts, colors, sizes, and spacing from Word
    • Images, which belong in Course Files
    • Page headers, footers, and page numbers
    • Comments and tracked-change markup
    • Anything that's really a picture, like a chart or a scanned page

    Word files versus PDFs

    A Word file knows what its parts are. A heading is marked as a heading and a list is marked as a list, so the conversion is close to exact. A PDF only knows where each word sits on the page. The converter works out headings from text size and lists from bullet characters, and it does a decent job, but tables come through as lines of text and you should read the preview before you copy. If you have the Word file, use it.

    Scanned PDFs, which are pictures of pages, have no text to read. The converter will tell you so rather than hand you an empty page.

    Headings you made by hand

    Lots of syllabi have headings that are really just a line of bold text. With Treat short bold lines as headings ticked, the converter turns those into real headings, which helps people using screen readers and anyone scanning on a phone. It only does this for short lines that are bold all the way through. If it gets one wrong, untick the box and the preview updates.

    Privacy and trust

    A syllabus usually isn't secret, but it's yours, and plenty of them carry phone numbers and office locations. Here's what actually happens to it.

    • Nothing is uploaded. Your browser reads the file and converts it on this page. There's no server behind this site to send it to, just the page itself, hosted on GitHub Pages.
    • The page can't phone home. Its security policy forbids it from making network requests to anyone, including me. You can check: open your browser's developer tools, switch to the Network tab, and convert a file. You'll see the page load its own files and nothing after that.
    • No account, no sign-in, no tracking. No analytics, no cookies, and no third-party code. Every library it uses is copied into the project and served from the same place as the page.
    • Nothing is saved. Close the tab and the file and the converted copy are gone. The only place the result goes is your clipboard, when you click Copy.

    The readable source is in canvsyllabus.js, and the libraries it uses are listed, with their licenses, in vendor.

    Beta software from one person

    I'm a Canvas administrator in higher education, and I wrote this because faculty shouldn't have to rebuild a syllabus by hand every time it moves from Word to Canvas. Your institution hasn't reviewed it. If that matters where you work, ask your own IT or Canvas team before you use it. I'd rather you ask than assume.

    When it gets something wrong

    Every syllabus is formatted a little differently, and some of them will trip this up. If the preview doesn't match your document in a way that matters, open an issue and tell me what went wrong and which program made the file. Please don't attach the syllabus itself unless you're comfortable with it being public.

    Page look out of date? GitHub can keep showing an older copy for a few minutes after an update. Hard-refresh with Ctrl + Shift + R, or Cmd + Shift + R on a Mac, and check that the version near the top matches the latest one on GitHub.
